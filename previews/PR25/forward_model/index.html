Forward model

The forward model is a function mapping the parameters of interest onto the predicted observables (in our case the counts in each bin).

Definition

In Refit.jl a linear template fit model is implemented. The model is a sum of components, each a simulated spectrum scaled by an activity. The predicted counts in energy bin $i$ are

\[\mu_i(\vec{a}) = \sum_k A_k(\vec{a}) \times h_{k,i} \times N\]

Here $h_{k,i}$ is the content of bin $i$ in the simulated spectrum of component $k$, $N$ is the factor norm, and $\vec{a}$ are the fit parameters. $A_k$ is the activity of component $k$:

  • by default it is a fit parameter of its own, $A_k = a_k$,
  • or it is a function of the fit parameters, $A_k = f_k(\vec{a})$, for example to tie the activities of two components together or to fit a half-life instead of an activity (see Activity functions below).

$N$ multiplies every component, also those whose activity is a function. If norm holds the unit conversions and the livetime, $A_k$ is the activity of source $k$, and an activity function returns an activity in the same units as a fit parameter. Usually the parameters are activities, and the model is written for that case. Any other choice of norm changes the meaning of $A_k$ in the same way.

build_forward_model turns a set of simulated energy spectra into such a function. This maps the parameters to the predicted counts in each energy bin.

Model components

The model is given as a dictionary with one entry per component. The key is a Symbol and names the component. The value gives its simulated spectrum and says where its activity comes from:

ValueActivity $A_k$Predicted counts in bin $i$
hparams[name]params[name] * norm * h[i]
(pdf = h, activity = f)f(params)f(params) * norm * h[i]

h is a Histogram of a simulated 1D energy spectrum in keV, h[i] its content in bin $i$, and params the named tuple of all fit parameters. All histograms must have the same binning. (pdf = h,) is the same as h. Any other key, such as a misspelled activty, is an error.

A component of the first form takes its parameter from its own name: the entry :K40_hpge_bulk needs params.K40_hpge_bulk. An activity function takes whatever it reads out of params, under any name, and several components can read the same parameter. A parameter missing from params raises an error at the first call of the model, naming the field it did not find. Parameters not used by any component are ignored.

Building the model

The examples in this manual use simplified spectra with three simulated sources, defined in example_data.jl. A real fit has many more sources. The simulated spectra are a dictionary of Histograms with the energy in keV, and all have the same binning:

# the names of the simulated spectra, these name the parameters
keys(mc_dict)
KeySet for a Dict{Symbol, StatsBase.Histogram{Float64, 1, Tuple{StepRangeLen{Float64, Base.TwicePrecision{Float64}, Base.TwicePrecision{Float64}, Int64}}}} with 3 entries. Keys:
  :K40_hpge_bulk
  :Pb212_to_Pb208_hpge_bulk
  :two_vbb_hpge_bulk
# keep the bins between 500 and 3200 keV
model, bin_edges = build_forward_model(
    mc_dict;
    e_low = 500,
    e_high = 3200,
    norm = 1e-3 * livetime,  # mBq to Bq, times the livetime in seconds
)

model is the function mapping parameters to predicted counts, bin_edges describes its bins (see below).

KeywordDefaultMeaning
e_low, e_high500, 4000Energy range in keV. Only bins fully inside are kept
blindnothing(min, max) in keV. Bins overlapping this range are removed
binning1Number of consecutive bins merged before the range is applied
norm1Factor $N$ multiplying every component

Calling the model

Here every component is of the first form, so the parameters are a flat named tuple with one activity per spectrum, named after the dictionary keys. The activities are in mBq, which norm converts to counts:

params = (
    K40_hpge_bulk = 40.0,
    Pb212_to_Pb208_hpge_bulk = 10.0,
    two_vbb_hpge_bulk = 100.0,
)

# predicted counts in each bin
pred = model(params)

pred is a flat vector with one entry per kept bin, here length(pred) = 270. Entry i is the sum over all spectra of activity * norm * (counts in the simulated bin). The order of the activities does not matter. A missing activity raises an error.

Activity functions

The activity of a component does not have to be a fit parameter of its own. For example, the activity of $^{208}$Tl is tied to that of $^{212}$Bi by the branching ratio of 35.94 %, so this component adds no parameter of its own:

:Tl208_cables => (pdf = h_Tl208, activity = p -> 0.3594 * p.Bi212_cables)

A function can also replace the activity by the quantity of interest. To fit the half-life of the $2\nu\beta\beta$ decay instead of its activity:

n_ge76 = 1.0e28  # made-up number of Ge-76 nuclei
year = 3.156e7   # s

components = merge(
    mc_dict,
    Dict(
        :two_vbb_hpge_bulk => (
            pdf = mc_dict[:two_vbb_hpge_bulk],
            # activity in mBq, with the half-life in units of 1e21 yr
            activity = p -> 1e3 * log(2) * n_ge76 / (p.T_half * 1e21 * year),
        ),
    ),
)
model_t, _ = build_forward_model(components; e_low = 500, e_high = 3200, norm = 1e-3 * livetime)
pred_t = model_t((K40_hpge_bulk = 40.0, Pb212_to_Pb208_hpge_bulk = 10.0, T_half = 2.2))

# the activity in mBq for a half-life of 2.2e21 yr
components[:two_vbb_hpge_bulk].activity((T_half = 2.2,))
99.83108373083667

The parameters of this model are K40_hpge_bulk, Pb212_to_Pb208_hpge_bulk and T_half. norm multiplies the 2νββ component like the others, so the function returns an activity in mBq.

get_priors only estimates a range for activities that are fit parameters. It skips the components with an activity function, and the parameters of their functions need a prior by hand, see Priors.

Each component separately

model(params, Val(:by_component)) returns a named tuple with the predicted counts of each component on its own, under the keys of the dictionary and in sorted order, whichever form the component has. get_best_fit_histograms uses this to draw the fit.

Bin edges

With blind the kept bins are not contiguous, so two vectors are returned instead of one edges vector.

Back to a histogram

counts_to_histogram turns the prediction into a Histogram, for example to plot the model at the best-fit parameters. It is the inverse of get_counts (see Likelihood).

# the prediction as a Histogram, for plotting
best_fit = counts_to_histogram(pred, bin_edges)
